# 多智能体设计（占位版）

> 状态：**设计 / UI 占位**，尚未接入执行链路。当前主控 Agent、MCP、技能与工具编排保持不变。
> 目标：在不破坏现有单主控 ReAct 的前提下，把复杂遥感任务拆成可审查的四角色流水线。

## 1. 四个角色

| 角色 | 核心职责 | 主要输入 | 主要输出 |
|---|---|---|---|
| **规划智能体** | 理解目标、拆解任务、选择技能/工具、生成执行计划与检查点 | 用户目标、项目上下文、可用技能/工具、数据范围 | `plan`：步骤、依赖、验收标准、风险 |
| **执行智能体** | 按计划调用影像检索、框选、解译、变化检测、数据/图层工具 | `plan`、工具契约、影像/图层 | `evidence`：图层、掩膜、统计、日志、产物路径 |
| **报告智能体** | 汇总执行证据、统计和图注，生成业务报告与专题图 | `plan`、`evidence`、模板/业务规则 | `report`：结论、图表、引用证据、导出文件 |
| **审查智能体** | 校验证据完整性、结果质量、权限与合规红线 | `plan`、`evidence`、`report`、验收标准 | `verdict`：通过 / 退回执行 / 退回规划，原因与整改项 |

## 2. 编排流程

```text
用户目标
  ↓
规划智能体 ── plan ──→ 执行智能体 ── evidence ──→ 报告智能体 ── report ──→ 审查智能体
  ↑                                                                          │
  └──────────────────── 退回规划（目标/计划问题）────────────────────────────┤
  └──────────────────── 退回执行（证据/质量不足）────────────────────────────┘
```

- 默认单轮闭环：规划 → 执行 → 报告 → 审查；
- 审查不通过时最多回退 2 轮，仍不通过则输出“未通过审查”的可追溯结论；
- 所有角色共享会话上下文与证据 ID，不直接向用户抢答；最终用户可见回复仍由主控 Agent 汇总。

## 3. 交接契约（草案）

```json
{
  "task_id": "uuid",
  "role": "planner|executor|reporter|reviewer",
  "plan": {
    "goal": "提取成都某区域建筑并统计变化",
    "steps": [{"id": "s1", "tool": "segment_image", "inputs": {}}],
    "acceptance": ["矢量与影像同源", "统计包含面积"]
  },
  "evidence": [
    {"id": "ev1", "type": "vector_layer", "layer": "cd_raster:...", "path": "..."}
  ],
  "verdict": {"status": "pass|revise_execution|revise_plan", "reasons": []}
}
```

## 4. 与现有系统的边界

- **主控 Agent** 仍是唯一用户可见回复者；
- `verification_agent` 保留，审查智能体后续可复用其校验结果；
- 执行智能体只调用已注册工具，不新增越权工具；
- 规划/审查阶段不直接操作 GeoServer 写接口，除非计划明确授权；
- UI 的「多智能体」面板当前只展示角色与职责，标注“占位”。

## 5. 后续落地顺序

1. 定义 `plan/evidence/report/verdict` 数据结构与事件协议；
2. 先实现“规划 → 执行 → 审查”三角色，报告沿用现有 `report_agent`；
3. 增加审查回退与最大轮次限制；
4. 最后开放 UI 编排、角色开关与运行轨迹。
