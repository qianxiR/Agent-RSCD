# Agent 核心能力与建设路线

## 1. 系统定位

Agent-RSCD 是面向自然资源遥感监测的可验证智能体系统。系统以主控 Agent 为唯一决策中心，通过遥感模型、GIS 工具和受控 worker 完成影像理解、语义分割、变化检测、定量统计、结果验证与监测报告生成。

核心建设原则：**先评估、再增强；先单智能体可靠性、再多智能体；先离线优化、再自进化。**

## 2. 当前核心功能

| 能力 | 当前实现 |
|---|---|
| 遥感影像理解 | 识别主要地物并描述位置、空间分布和场景特征 |
| 语义分割 | 按建筑、道路、水体、裸地、植被、农田等类别生成掩膜、矢量图斑和面积统计 |
| 变化检测 | 对双时相影像提取变化区域，统计变化像素、占比、连通区域和分类面积，并生成变化图层 |
| 工具执行 | 主控 Agent 按 ReAct 循环选择遥感、GeoServer、数据库、沙盒、导出和报告工具 |
| 计划状态 | 工具任务具备持久化步骤、执行状态、证据记录和完成门，未验证步骤不能直接宣告完成 |
| 结果校验 | `verification_agent` 使用确定性规则检查工具状态、数量信号和产物路径，失败后生成 `repair_plan` |
| 异常恢复 | 支持参数修正、替代工具、重复失败拦截、停止回滚和修复结果审计 |
| 记忆管理 | 管理近期消息、会话摘要、任务工作状态、长期偏好及通过证据门的 accepted lesson |
| 技能编排 | 通过受控技能契约选择分割、变化检测和 GeoServer 发布流程，并将技能步骤写入计划 |
| 报告生成 | 分割完成后由同步 `report_agent` 回读证据并生成自然资源监测 PDF |

当前执行闭环：

```text
用户请求
→ 主控 Agent 理解任务并选择工具或技能
→ 建立或恢复 plan state
→ 执行工具
→ verification_agent 校验结果
→ passed: 推进步骤
→ failed/warning: 根据 repair_plan 修正
→ completion gate 通过
→ 返回结论并沉淀合格 lesson
```

## 3. 当前能力边界

- 意图理解主要依赖模型、系统提示词和工具描述，尚未形成统一的结构化任务模型（`monitoring_task_spec`）；已有 plan/step/completion_gate 执行闭环与 verification/repair worker，但缺结构化任务规格与产物/证据血缘模型（详见 [engineering-gap-analysis.md](core/engineering-gap-analysis.md)）。
- 已有计划状态机（plan/step/completion_gate）、确定性验证和修复策略，但当前计划仍是单版本内存模型，尚不具备成熟的分层任务拆解、依赖图规划和局部动态重规划（无 plan 版本链）。
- `verification_agent` 是确定性校验 worker，`report_agent` 是同步报告 worker；当前不是开放式多智能体协作系统。
- 已有行为、修复成功率和固定场景评估，但尚未形成效果、时延、令牌费用、GPU/内存占用和任务预算的一体化基线（token 仅打日志不落库，无 GPU 采集）。
- accepted lesson 可影响后续上下文和技能选择，但不会自动训练模型权重，也不等同于 RLHF 或在线自进化。
- 遥感专业能力已覆盖基础分割、变化区域和统计结果；精细类别转移、扩张/收缩/转型判定、语义不确定性校准仍需专门数据和评估集支持（当前 `change_mask` 只编码变化后类别，缺 from→to 转移矩阵）。

## 4. 核心目标

在现有基础自主调用和简单规划能力之上，逐步建设具备以下能力的智能体系统：

- 准确理解用户意图、任务约束、输入输出和成功条件。
- 完成复杂任务拆解、多步规划与局部动态重规划。
- 稳定执行工具调用、异常恢复、权限控制和结果验证。
- 管理短期上下文、工作状态与长期记忆。
- 支持 Supervisor 中心调度下的专业 Agent 分工、协同和结果校验。
- 建立效果、效率、资源成本一体化评估体系。
- 基于遥感数据、失败案例、人工反馈和运行记录形成持续迭代闭环。

## 5. 实现顺序

| 阶段 | 建设重点 | 关键产出 |
|---:|---|---|
| 1 | 可观测性与评估基线 | 全链路 Trace、错误分类、固定测试集、效果/效率/成本基线 |
| 2 | 意图理解与任务建模 | 结构化目标、约束、输入、输出、风险和成功条件 |
| 3 | 规划与执行升级 | 分层计划、依赖关系、检查点、状态恢复和局部动态重规划 |
| 4 | 工具调用可靠性 | 工具契约、参数校验、权限分级、超时、重试、熔断和结果验证 |
| 5 | 记忆与上下文管理 | 工作记忆、上下文压缩、检索式长期记忆、冲突和时效管理 |
| 6 | 动态决策与结果校验 | 有限反思、计划校验、异常恢复、证据融合和不确定性表达 |
| 7 | 效率与成本优化 | 模型路由、可并行步骤执行、缓存、上下文预算和任务预算 |
| 8 | 多智能体协同 | Supervisor 调度、专业 Agent 权限、任务协议、共享证据和冲突裁决 |
| 9 | 持续迭代与自进化 | 失败样本回流、人工反馈、离线 SFT/偏好优化、灰度评估和策略发布 |

阶段按顺序设置质量门。前一阶段没有稳定指标和回归基线时，不扩大后一阶段的自主性与执行权限。

## 6. 一体化评估目标

| 维度 | 核心指标 |
|---|---|
| 效果 | 意图解析准确率、任务成功率、工具选择准确率、参数正确率、计划完成率、结果验证通过率、遥感分割/变化检测指标、不确定性校准 |
| 效率 | 端到端时延、首响应时延、工具调用次数、重规划次数、并行收益、缓存命中率、上下文长度 |
| 成本 | 模型输入/输出令牌、单任务模型费用、GPU 时间与显存峰值、CPU/内存占用、存储与外部服务调用量 |
| 可靠性 | 错误恢复率、错误成功率、重复失败率、超时率、权限违规率、产物可用率 |
| 协同 | 任务分派正确率、worker 完成率、结果一致性、冲突解决率、Supervisor 额外开销 |

所有策略、提示词、模型和工具版本均以同一评估集进行离线对比；只有效果不退化、效率和成本满足门槛的版本才能进入灰度验证。

## 7. 持续迭代闭环

```text
运行 Trace 与人工反馈
→ 失败分类和高价值样本筛选
→ 遥感指令数据、工具轨迹和偏好数据构建
→ 提示词/策略优化或离线 SFT、DPO/RLAIF
→ 固定评估集回归
→ 小流量灰度验证
→ 版本发布、监控与必要时回滚
```

在线系统只负责记录、检索和受控应用已验证经验；模型权重更新、技能升级和决策策略更新必须经过离线训练、独立评估和版本化发布。
