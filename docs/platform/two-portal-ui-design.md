## 一、两套门户的定位

| 维度 | 用户端 | 管理端 |
|---|---|---|
| 使用者 | 分析员、项目成员、访客 | 系统管理员、组织管理员 |
| 核心任务 | 做项目、传数据、跑分析、看结果、出报告 | 管人、管项目、管数据、管服务、管审计 |
| 数据范围 | 自己参与的项目 | 全系统 |
| 视觉 | 浅色、蓝色强调、任务导向 | **同一套浅色蓝白令牌**；白色侧栏 + 更密表格 + 管理控制台标识 |
| 入口 | `/`（工作台，默认） | `/admin/**`（同一应用的独立路由区，独立布局与登录） |
| Agent | 工作台内置 Copilot 对话（已有） | 不提供 |

> **已确认（2026-10-27）**：用户端**沿用现有工作台**（Agent 对话 + 地图 + 图层管理）作为最终形态；
> 工作台与管理端是**两个不同内容区**，用 **Vue Router 分流**：默认进工作台，工作台右上角「管理控制台」
> 进入 `/admin`。不再新建用户端 SPA，也不再单独出 `admin.html` 入口。
> 管理端仍保留强制 TOTP；生产若需要独立子域，可在 nginx 把 `admin.*` 反代到同一份 dist 的 `/admin` 路由。

> **已确认**：管理端不使用深色侧栏/橙色主题，保持与当前前端一致的浅色、蓝色强调、紧凑密度；通过“管理控制台”标题、环境标识、更密表格和危险操作规范来区分，而不是换一套视觉语言。

> **不要用“同一套菜单 + 判断角色隐藏”** 做两套门户。菜单结构、默认页、危险操作、审计要求都不同，建议两个 SPA、共享组件库与设计令牌。

```text

┌────┬────────────┬────────┬──────┬────────┬────────┬────────┐

### 3.5 数据治理

- 全量数据集表格：类型/项目/CRS/大小/状态/来源；
- 质量筛选：缺 CRS、空文件、重复 checksum、长期未使用、孤儿文件；
- 操作：修复元数据、重新解析、迁移存储、删除孤儿、导出清单；
- 保留策略：按项目/类型设置天数；
- 存储清理任务化，不在请求里同步删。

### 3.6 图层服务

- GeoServer 健康：版本、响应时间、工作空间数、图层数；
- 工作空间/图层表格：类型、bbox、样式、引用项目；
- 操作：重发布、换样式、删除（需确认）、批量清理；
- 失败发布任务列表 + 重试。

### 3.7 任务与模型

│128 │ 变化检测  │ 成都    │ 张三 │ 运行62%│ 01:23    │ 取消   │
└────┴──────────┴────────┴──────┴────────┴──────────┴────────┘
```

- Worker 页：主机、GPU、显存、心跳、当前任务；
- 模型页：模型名/提供方/参数/默认开关/启用；
- 操作：重试、取消、调整并发、GPU 队列权重。

### 3.8 存储与配额

- 总容量/已用/增长趋势；
- 按组织/项目 Top 列表；
- 配额编辑（软限制提醒/硬限制禁止上传）；
- 清理任务、回收站、生命周期策略。

### 3.9 审计日志

```text
审计日志                      [导出 CSV]
[全部] [登录] [权限] [数据] [任务] [系统]
时间 | 操作者 | 动作 | 对象 | IP | 结果 | 详情
```

- 详情抽屉展示 before/after diff；
- 支持按 request_id 追踪；
- 审计只读，不允许编辑/删除；
- 导出需权限并记审计。

### 3.10 系统设置

分组：

1. **安全**：密码策略、登录失败锁定、MFA、会话时长、IP 白名单；
2. **认证**：SSO/OIDC、LDAP；
3. **存储**：MinIO 配置、桶、生命周期；
4. **任务**：并发、超时、队列上限、GPU 分配；
5. **通知**：邮件/SMS/Webhook；
6. **功能开关**：Agent、报告模板、实验功能；
7. **公告**：用户端顶部通知。

所有设置修改需“保存 + 原因 + 审计”；敏感值脱敏显示。

## 四、用户端与管理端的视觉区分

**同一套设计令牌，不同的使用密度和导航结构**。不换配色，避免用户在两套系统间切换时产生割裂。

| 维度 | 用户端 | 管理端 |
|---|---|---|
| 背景 | `#f5f6f8` | `#f5f6f8`（一致） |
| 面板 | `#ffffff` | `#ffffff`（一致） |
| 强调色 | `#2c6fbd` | `#2c6fbd`（一致） |
| 侧栏 | 现有工作台三栏：左栏项目/会话 + 中间地图 + 右侧 Copilot | 212px 菜单，白色；选中浅蓝底 + 蓝色左边条 |
| 标题 | 工作台顶栏（16px 品牌 + 状态点） | 18px，略紧凑 |
| 正文/表格 | 13px | 12px，治理表格更密 |
| 品牌区 | 国土智察 · 自然资源遥感智能监测系统 | 国土智察 · 管理控制台 |
| 环境标识 | 无 | 顶部“生产环境”浅橙标签 |
| 危险操作 | 红色按钮 | 红色描边 + 必须填写原因 |
| 首页 | 工作台（会话 + 地图 + Copilot） | 运营总览 |

> 管理端的“控制台感”来自：**更宽的菜单 + 更高密度的表格 + 全局范围 + 环境标识 + 审计原因**，不是深色皮肤。
>
> 参考原型：`docs/platform/admin-ui-mockup.html`（浅色白侧栏，和用户端同风格）。

## 五、权限驱动的 UI

### 5.1 路由守卫

```js
// 伪代码
router.beforeEach(async (to) => {
  if (to.meta.public) return true
  if (!auth.hasToken()) return '/login'
  const me = await auth.loadMe()          // /api/v1/me
  if (to.meta.admin && !me.roles.includes('system_admin') && !me.roles.includes('org_admin')) {
    return '/403'
  }
  if (to.meta.permission && !me.permissions.includes(to.meta.permission)) {
    return '/403'
  }
  return true
})
```

### 5.2 按钮级

```vue
<PermissionGate permission="user:manage">
  <button class="btn danger">禁用用户</button>
</PermissionGate>
```

- 无权限：隐藏或禁用 + tooltip 说明；
- 管理端危险操作：`ConfirmDanger` 组件，必须填原因；
- 后端仍要独立校验，前端权限只影响体验。

### 5.3 管理端“进入用户项目”

- 默认只读查看；
- 顶部显示“管理员只读模式”条；
- 所有访问写审计；
- 不允许在 impersonate 模式下执行写操作（除非显式二次授权）。

## 六、登录与安全交互

### 6.1 登录页

- 用户端与管理端共用登录组件，但管理端增加：
  - 独立子域 + 环境标识；
  - **强制 MFA 第二步**（TOTP 6 位；首次登录绑定密钥 + 备用恢复码）；
  - “仅管理员可登录”提示；
  - 登录失败次数提示；MFA 失败同样限流。
- 登录成功：
  - 用户端 → `app.example.com/projects`
  - 管理端 → `admin.example.com/overview`
- 管理端未绑定 MFA 的账号：登录后强制进入绑定页，未绑定前不能访问任何管理 API。

### 6.2 会话

- 顶部用户菜单：个人信息、修改密码、会话设备、退出；
- 管理端可“退出所有设备”；
- access token 过期静默刷新；刷新失败跳登录。

### 6.3 错误态

- 401：跳登录，保留 returnUrl；
- 403：`/403` 页面 + 返回项目；
- 429：提示稍后重试；
- 5xx：错误页 + request_id，方便排查。

## 七、前端工程结构（两套 SPA）

建议 monorepo / 或同仓两入口：

```text
frontend/
├── packages/
│   ├── ui-kit/                 # 共享组件/令牌/图表
│   ├── api-client/             # 请求封装/类型
│   └── auth/                   # token/refresh/权限
├── apps/
│   ├── user/                   # 用户端 SPA
│   │   └── src/{pages,components,router,stores}
│   └── admin/                  # 管理端 SPA
│       └── src/{pages,components,router,stores}
└── nginx/
```

- 共享：按钮/表格/弹窗/表单/图表/权限组件/请求库。
- 不共享：菜单、页面、store、路由。
- 构建产物：`dist/user` → `app.example.com/`，`dist/admin` → `admin.example.com/`。
- 如果短期不想拆仓：先在同一 Vite 工程用两个入口 `index.html` / `admin.html`，但路由和 store 必须分开。

### 7.1 管理端组件清单

| 组件 | 用途 |
|---|---|
| `AdminShell` | 白色 212px 侧栏 + 顶栏 + 环境标识（沿用用户端令牌） |
| `DataTable` | 高密度表格、列配置、批量选择 |
| `FilterBar` | 关键词/状态/时间/组织 |
| `StatCard` | KPI |
| `TrendChart` | 任务/存储趋势（SVG 起步） |
| `AuditDiff` | before/after diff |
| `ConfirmDanger` | 原因输入 + 二次确认 |
| `PermissionMatrix` | 角色权限矩阵 |
| `EnvBadge` | DEV/STAGING/PROD |

### 7.2 当前实现结构（阶段 26 / 27 / 28）

不拆仓、不拆入口：**单应用 + Vue Router 分流**，管理端页面按需异步加载。

```text
frontend-vue/
├── index.html                 # 唯一入口
└── src/
    ├── main.js                # 装配 Pinia + ElementPlus + Router
    ├── App.vue                # <RouterView />
    ├── router/index.js        # / → 工作台；/admin/** → 管理端（守卫 + 权限）
    ├── views/WorkbenchView.vue# 工作台挂载点（WS 连接/断开）
    ├── layouts/, components/  # 现有工作台源码（功能不动）
    ├── admin/                 # 管理端: layouts / pages（异步 chunk）
    └── shared/                # api / auth / ui / styles / utils
```

- 默认路由 `/` 是工作台；工作台右上「管理控制台」→ `/admin`，未登录跳 `/admin/login`。
- 管理端路由 meta 带 `permission`，守卫逐页校验；非管理员进 `/admin/403`。
- 不共享：菜单、页面、store。共享：设计令牌、基础组件、请求库、认证工厂。
- 管理端会话命名空间 `rsiis_admin_*`，与工作台 `rsiis_token` 互不覆盖。

## 八、关键交互流程

### 8.1 邀请用户

1. 管理员点“邀请用户”；
2. 输入邮箱/用户名，选择组织/角色/项目；
3. 发送邀请（邮件/链接）；
4. 用户设置密码/首次登录；
5. 管理员在列表看到“待激活”，可重发/撤销。

### 8.2 禁用用户

1. 用户行 → 禁用；
2. 二次确认 + 原因；
3. 后端撤销 refresh token/会话；
4. 审计记录；
5. 用户端下次请求 401。

### 8.3 处理失败任务

1. 任务列表筛选失败；
2. 详情看错误/日志/资源；
3. 重试（可改参数）或取消；
4. 重试生成新 job，保留原 job 供审计。

### 8.4 存储告警

1. 总览告警 → 存储页；
2. 按项目看占用；
3. 调整配额/清理孤儿；
4. 清理任务异步执行，完成后通知。

## 九、响应式与可访问性

- 管理端以桌面为主：≥1280 最佳；<1024 侧栏折叠为图标。
- 表格横向滚动，关键列固定（名称/操作）。
- 所有图标按钮有 `aria-label`；危险操作不能仅靠颜色。
- 键盘：`Ctrl/Cmd+K` 搜索，`Esc` 关闭抽屉。
- 对比度满足 WCAG AA；表格行高 ≥ 40px。
