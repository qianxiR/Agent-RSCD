# Agent 目标 Spec

本文是后端 Agent 架构建设的外部真相源。后续实现、重构、worker 拆分、记忆和技能设计都以本文为准。

## 1. 总目标

构建一个面向遥感解译任务的智能体执行系统, 让 Agent 在运行过程中具备记忆、反思、持续自主迭代能力, 并能够按计划分配专业子 Agent 完成受控子任务。

核心工程难点:

```text
在有限且会腐烂的上下文里, 让 Agent 始终基于最新证据做出可验证决策。
```

这意味着后续所有架构改造都必须服务于三件事:

| 方向 | 目的 |
|---|---|
| 上下文控制 | 让模型看到当前有效目标、最新证据和明确边界 |
| 行为验证 | 不相信“已完成”, 只相信工具结果、产物、日志和验证结论 |
| 状态连续性 | 让多轮任务持续知道当前做到哪里、失败原因是什么、下一步怎么改 |

系统目标不是“多个 Agent 自由讨论”, 而是形成主控式执行闭环:

```text
用户目标
→ 主控 Agent 规划任务
→ 分配专业 worker
→ worker 调用工具或执行专业逻辑
→ worker 汇报结构化结果
→ verification_agent 做客观验证
→ 主控 Agent 根据汇报和验证结果实时决策
→ 继续执行、修正、请求最小用户输入或收尾
→ 经验沉淀到记忆, 高频流程升级为 skill
```

## 2. 当前有效决策

| 决策 | 当前结论 |
|---|---|
| 多 Agent 形态 | 主控 Agent + 专业 worker |
| 主控 Agent | 唯一决策中心和唯一用户可见回复者 |
| worker | 只执行受控子任务, 完成后结构化汇报 |
| 验证 Agent | 第一阶段使用确定性规则, 不默认调用 LLM |
| 任务状态源 | 复用 `ai_task`, 不新增第二套任务表 |
| 工具结果回灌 | 统一走 `runtime\observation_builder.py` |
| prompt 组织 | 静态模板、动态上下文、工具目录、构建器分离 |
| 错误修正 | `repair_policy` 输出 `repair_plan`, 主控 Agent 继续决策 |
| 记忆沉淀 | 只沉淀有泛化价值的 lesson / workflow / envfact |
| 技能升级 | 高频稳定流程先沉淀 lesson, 再升级 skill |

## 3. 架构范式

本项目采用 plan-driven multi-agent orchestration:

```text
主控 Agent 制定 plan
→ 主控 Agent 派发子任务
→ 子 Agent 在权限内执行
→ 子 Agent 返回结构化汇报
→ 主控 Agent 读取汇报和验证结果
→ 主控 Agent 决定下一步
```

不采用群体辩论式架构。

| 角色 | 定位 | 权限边界 |
|---|---|---|
| 主控 Agent | 唯一决策中心, 负责理解目标、规划任务、分配子任务和最终回复 | 可以调度 worker 和工具, 负责是否继续、修正或收尾 |
| 专业 worker | 受控执行单元, 负责验证、遥感、发布、报告等专业子任务 | 只能在角色权限内执行, 完成后向主控 Agent 汇报 |
| 工具 | 真实动作执行层 | 只执行具体能力, 不承担最终决策 |
| 记忆系统 | 经验沉淀层 | 保存偏好、事实、已学教训和已学流程, 不替代当前工具事实 |
| 技能系统 | 成熟流程固化层 | 提供标准执行方案, 不替代主控 Agent 当前决策 |

## 4. 非目标 / 禁止事项

以下内容不是当前目标:

- 不做开放式 Agent 群聊。
- 不做多个 Agent 投票或辩论决策。
- 不允许 worker 直接向用户输出最终结论。
- 不允许 worker 递归无限分配子任务。
- 不允许长期记忆覆盖当前工具事实。
- 不允许工具失败后伪装成功。
- 不允许没有 verification、产物、数量或日志证据就最终收尾。
- 不允许同一工具、同一参数、同一失败原因机械重复。
- 不允许 skill 绕过主控 Agent 成为隐藏执行器。

## 5. 核心运行闭环

核心闭环是任务、规划、实时汇报和反馈的连续过程:

```text
任务规划
→ 子任务分配
→ 工具执行
→ 结果验证
→ worker 汇报
→ 主控 Agent 决策
→ 下一步执行
```

每一轮必须回答:

| 问题 | 判断依据 |
|---|---|
| 当前目标是什么 | 当前用户输入、任务状态卡、会话摘要 |
| 当前做到哪里 | 近期消息、工具调用链、worker 状态 |
| 当前结果是否可信 | verification、agent_validation、产物存在性、数量字段 |
| 下一步怎么做 | repair_plan、任务计划、工具契约、worker 汇报 |

## 6. 主控 Agent 与子 Agent 边界

主控 Agent 职责:

- 理解用户目标和约束。
- 维护全局任务计划。
- 决定是否调用工具或分配 worker。
- 接收 worker 汇报和验证结果。
- 判断继续执行、切换策略、请求用户输入或最终回复。
- 触发记忆沉淀和技能复用。

子 Agent 职责:

- 接收明确子任务目标。
- 在受限工具和受限权限内执行。
- 输出结构化结果。
- 汇报证据、问题、建议和阻塞点。
- 不直接向用户给最终结论。
- 不递归创建无限子任务。

信息优先级:

```text
当前用户明确要求
> 最新工具客观结果
> 最新 agent_validation / repair_plan
> worker 结构化汇报
> 当前任务状态卡
> 近期历史消息
> 会话摘要
> 长期记忆 / skill
```

当历史记忆与当前工具结果冲突时, 必须优先信任当前可验证结果。

## 7. 记忆、反思、技能的关系

| 能力 | 解决的问题 | 生命周期 |
|---|---|---|
| 反思 | 当前失败后下一步怎么改 | 当前任务内 |
| 记忆 | 下次遇到同类问题如何避免重犯 | 跨会话 |
| 技能 | 高频稳定流程如何标准化执行 | 长期复用 |

演进路径:

```text
一次失败
→ repair_plan 做当前修正
→ 修正成功后沉淀为 lesson
→ 多次稳定出现后升级为 skill
```

示例:

```text
本地文件不存在
→ 当前轮 repair_plan: 不重复同一路径, 请求有效路径或上传文件
→ 记忆: missing_input_file 不应沙盒兜底
→ 技能: 遥感任务开始前先检查输入路径和文件可读性
```

## 8. 成功验收标准

系统达到目标时应满足:

- 主控 Agent 能显式维护任务计划和当前状态。
- worker 能完成受控子任务并结构化汇报。
- 工具失败后不会伪装成功。
- `agent_validation.failed/warning` 后不会直接收尾。
- 同一工具、同一参数、同一失败原因不会机械重复。
- 修正成功的错误模式能沉淀为长期教训。
- 高频稳定流程能升级为 skill。
- 用户只在缺少必要外部信息时被请求介入。
- 最终回复基于客观证据、worker 汇报和验证结果。
